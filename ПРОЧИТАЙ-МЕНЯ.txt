EKT SMART — УМНЫЕ ЗАКУПКИ
Локальный прототип для HACKALEM AI / Электрокомплект

БЫСТРЫЙ ЗАПУСК
1. Извлеките ZIP целиком в обычную папку.
2. Дважды нажмите «Запустить.bat» или откройте EKT-Smart.html.
3. Если браузер по умолчанию не открыл приложение, перетащите HTML в актуальный Microsoft Edge или Google Chrome.
Python, Node.js, сервер, интернет и платные ключи не нужны.
Не запускайте HTML прямо внутри ZIP: сначала извлеките файлы.
Первая генерация и расчёт занимают несколько секунд.

ЧТО ВНУТРИ
— 30 товаров, 2 склада, 3 поставщика, 24 месяца синтетических продаж.
— Обзор, рекомендации, карточка товара, будущее склада, детектив продаж, заказы, данные и настройки.
— Учёт сезонности, тренда, дополнительных планов роста, stockout, аномалий, остатков и дат входящих поставок.
— Сценарии задержки поставок и изменения спроса.
— Ручное решение по разовым покупкам.
— Черновики, редактирование, утверждение, Excel/CSV экспорт.
— Импорт XLSX и CSV по шаблону, экспорт исходных данных, JSON резервная копия.
— Локальное сохранение в IndexedDB, без передачи данных на сервер.

ВАЖНО О СОХРАНЕНИИ
Работайте с одним файлом в одной папке в одном браузере.
Перемещение файла, смена браузера, приватный режим или очистка данных браузера могут сделать сохранения недоступными.
Регулярно скачивайте JSON резервную копию в разделе «Данные и настройки».
Она содержит продажи, настройки, решения по аномалиям и заказы.
Excel экспорт данных НЕ содержит решений и заказов; для переноса всей работы используйте JSON.
Если браузер запретит сохранение, программа покажет предупреждение.

ДЕМОНСТРАЦИЯ ЗА 4 МИНУТЫ
1. Обзор: покажите срочные товары и сумму закупки.
2. Рекомендации: выберите склад и откройте кабель EKT-001. Покажите формулу количества.
3. Детектив: у EKT-001 найдите покупку 5 000 м, измените «Автоматически» на «Регулярный спрос». Покажите изменение прогноза. Верните автоматическое решение.
4. Будущее склада: выберите дату, задержку +5 дней и сравните линии остатков. Сценарий не меняет документы.
5. Рекомендации: «Выбрать нужные» → «Создать черновики».
6. Измените количество, утвердите заказ, скачайте Excel.
7. Данные: скачайте резервную копию.

ИМПОРТ
Скачайте пустой XLSX-шаблон в приложении. Названия листов и столбцов менять нельзя.
Для образца заполнения скачайте текущие демонстрационные данные в Excel.
Поддерживается XLSX, не старый XLS. Макросы и формулы не выполняются. Формулы читаются только при наличии сохранённого значения; лучше вставить значения.
Допустимый файл до 30 МБ, распакованные XLSX до 100 МБ. ZIP64 и защищённые паролем книги не поддерживаются.
Даты: ГГГГ-ММ-ДД; числовые даты Excel также читаются (стандартная система 1900).
CSV: UTF-8, разделитель ; или ,; десятичная запятая допустима внутри кавычек.
Для CSV выберите соответствующую таблицу. Импорт заменяет таблицу целиком, а не дописывает строки.
Рекомендуется первый импорт выполнить одним XLSX со всеми листами, чтобы не смешать свои справочники с демоданными.
Листы без строк тоже заменяют таблицу пустой. Непереданные листы остаются прежними.
При ошибках весь импорт отменяется. Отображаются первые 30 ошибок; исходные данные остаются неизменны.
Импорт сбрасывает решения по аномалиям; ранее созданные заказы остаются документами с сохранёнными названиями и ценами строк.
Статус поставки: confirmed (подтверждена) или pending (не подтверждена).
Остатки — один актуальный снимок на пару артикул/склад, а не история снимков.
При импорте inventory расчётная дата берётся из первой строки. Все остатки должны относиться к одной дате.
Клиенты: только обезличенные ID. Не загружайте имена, телефоны и адреса.
Лишние столбцы в таблицах не сохраняются.
Формат реального V2/1С не предоставлен. Прямой адаптер к нему не реализован. Excel/CSV — документированный формат обмена; совместимость с конкретной конфигурацией 1С требует проверки.

МЕТОДИКА
Единица расчёта: артикул + склад. Продажи с расчётной даты и позднее не используются.
Крупные покупки агрегируются по клиенту и дню. Порог = максимум из 5 медиан, медиана + 8*max(1,MAD), 20 единиц.
Покупки выше порога считаются разовыми, если у клиента менее 3 крупных покупок в истории. Ручное решение имеет приоритет. Реальные записи продаж не удаляются.
Это эвристика: она требует проверки закупщиком, особенно для редкого спроса и долгих проектов.
Полные дни stockout заполняются средним спросом сопоставимого дня недели в пределах ±56 дней. Если таких дней нет, берутся последние 90 доступных дней.
Будущие относительно stockout наблюдения могут использоваться только из истории до расчётной даты. Для backtest нужно заново обрезать историю на каждую дату.
Сезонность по месяцам применяется при >=650 днях истории, коэффициент ограничен диапазоном 0,25–4. Перед оценкой коэффициентов удаляется линейный тренд, оценённый по разнице сопоставимых дней с интервалом 365 дней.
Уровень — средний очищенный от сезонности спрос за последние 56 дней. Тренд — линейная регрессия по последним 180 дням очищенного от сезонности спроса, пересчитанная в дневной темп относительно текущего уровня, с ограничением ±0,5%. Продолжение тренда ограничено 90 днями.
Дополнительный прирост категории применяется поверх исторического тренда. По умолчанию 0%, чтобы не дублировать наблюдаемый рост.
Категория влияет через настройки прироста, пересмотра и страхового запаса.
При короткой истории годовая сезонность не применяется, показывается предупреждение. Для совсем нового товара без продаж прогноз 0: экспертный стартовый запас не угадывается.
Потребность = max(0, прогноз на срок поставки + период пересмотра + страховой запас - текущий остаток - подтверждённые поставки внутри периода).
Страховой запас — прогноз на заданное число дополнительных дней.
Положительная потребность округляется вверх с учётом минимальной партии и упаковки.
Поставка в дату начала расчёта приходит до дневного спроса. Поставка за пределами горизонта и просроченная поставка не вычитаются из потребности.
График отдельно моделирует каждый день, поэтому поздняя поставка не скрывает ранний дефицит.
Новая закупка приходит только через lead_time_days; ранний дефицит может потребовать ускорения или перемещения.
Физический остаток ограничен нулём. Неудовлетворённый спрос — потерянные продажи, не задолженность.
Покрытие = остаток / средний прогноз на ближайшие 14 дней, без входящих поставок.
Излишек = текущий остаток больше суммарного прогнозируемого спроса на дни 0–60 включительно.
Срочность высокая при первом дефиците не позже срока новой поставки; средняя — до конца периода закупки; иначе плановая.
В «Будущем склада» количество нового заказа остаётся исходным, а сценарий проверяет достаточность этого заказа при изменённых условиях.

ОГРАНИЧЕНИЯ
Это работающий автономный прототип, а не промышленная ERP.
Он использует HTML/CSS/JavaScript вместо ранее предложенных Next.js/Python, чтобы запускаться без установки окружения.
Здесь нет нейросетевого API: рекомендации рассчитываются статистическим алгоритмом, объяснения формируются по его числам.
Нет серверной авторизации, многопользовательской работы, обмена между компьютерами, автоматической отправки, прямой интеграции 1С, оптимизации бюджета или резервов клиентских заказов.
Поставщик один на артикул, срок поставки один на поставщика. Частичные stockout не моделируются.
Точность на реальных данных компании не измерена; экономический эффект не заявляется.
На больших наборах пересчёт может занимать время; обработка идёт в основном потоке браузера.
Используйте обезличенные данные и резервные копии.

ДЛЯ РАЗРАБОТЧИКА
Исходники находятся в папке source, не нужны для обычного запуска.
engine.js — расчёты; ui.js — интерфейс и импорт; files.js — XLSX/CSV; style.css — оформление.
Проверка расчётного ядра: node source/test.cjs.
Сборка HTML: node source/build.cjs (использует папку родительского приложения).
В CHECKS.txt указаны выполненные проверки и их результаты.
